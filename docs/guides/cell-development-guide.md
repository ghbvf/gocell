# Cell Development Guide

## What Is a Cell

A Cell is the core business unit in GoCell, encapsulating a set of related Slices (feature cuts). Each Cell has independent data ownership, a consistency level, and a lifecycle. Cells communicate through Contracts; direct imports of another Cell's `internal` packages are forbidden. GoCell ships three built-in Cells: `configcore` (configuration management), `accesscore` (authentication and authorization), and `auditcore` (audit tracking).

## Creating a Custom Cell

### 1. Define the Directory Structure

```
cells/
└── mycell/
    ├── cell.go              # Cell entry point (implements cell.Cell interface)
    ├── cell.yaml            # Metadata declaration (required)
    ├── cell_test.go
    └── slices/
        └── myslice/
            ├── slice.yaml   # Slice metadata
            ├── service.go   # Business logic
            ├── handler.go   # HTTP handler
            └── service_test.go
    └── internal/
        ├── domain/          # Domain model
        ├── ports/           # Driving-side interfaces (Repository, etc.)
        └── mem/             # In-memory implementation (for development/testing)
```

### 2. Declare cell.yaml

```yaml
id: mycell
type: core
consistencyLevel: L1
lifecycle: experimental  # optional, defaults to experimental; values: experimental|candidate|asset|maintenance|retired
owner:
  team: my-team
  role: mycell-owner
schema:
  primary: my_table
verify:
  smoke:
    - mycell/smoke
```

### 3. Implement the Cell Interface

Cell metadata is generated by codegen from `cell.yaml` into `cell_gen.go` (**do not hand-write metadata literals** — the single source of truth is the yaml).

First add `goStructName: MyCell` to `cell.yaml` to enable cellgen:

```yaml
# cell.yaml (continued from above)
goStructName: MyCell
```

Then run `go run ./cmd/gocell generate cell --all` to produce `cell_gen.go`:

```go
// cell_gen.go — Code generated by gocell generate cell. DO NOT EDIT.
package mycell

var cellMeta = &metadata.CellMeta{
    ID:               "mycell",
    Type:             "core",
    ConsistencyLevel: "L1",
    Lifecycle:        "experimental",
    Owner:            metadata.OwnerMeta{Team: "my-team", Role: "mycell-owner"},
    Schema:           metadata.SchemaMeta{Primary: "my_table"},
    Verify:           metadata.CellVerifyMeta{Smoke: []string{"mycell/smoke"}},
    GoStructName:     "MyCell",
}

func loadCellMetadata() *metadata.CellMeta { return cellMeta }
```

You only hand-write `cell.go`, calling the generated `loadCellMetadata()` during construction:

```go
// cell.go
package mycell

import (
    "context"
    "log/slog"

    "github.com/ghbvf/gocell/framework/kernel/cell"
    "github.com/ghbvf/gocell/framework/kernel/clock"
)

// ISP split: cell.Cell is decomposed into four focused interfaces. Each assertion
// independently verifies compliance at compile time.
// ref: docs/architecture/202605101800-adr-cell-interface-isp-split.md §D3
var (
    _ cell.CellIdentity  = (*MyCell)(nil)
    _ cell.CellLifecycle = (*MyCell)(nil)
    _ cell.CellStatus    = (*MyCell)(nil)
    _ cell.CellInventory = (*MyCell)(nil)
)

type MyCell struct {
    *cell.BaseCell
    clk    clock.Clock
    logger *slog.Logger
    // ... dependency fields
}

func NewMyCell(clk clock.Clock, opts ...Option) *MyCell {
    clock.MustHaveClock(clk, "mycell.NewMyCell")
    c := &MyCell{
        BaseCell: cell.MustNewBaseCell(loadCellMetadata()),
        clk:      clk,
        logger:   slog.Default(),
    }
    for _, o := range opts {
        o(c)
    }
    return c
}

func (c *MyCell) initInternal(ctx context.Context, reg cell.Registrar) error {
    // User hook: cell_gen.go's Init already calls BaseCell.Init + drains
    // RouteGroup/Subscribe markers. Business dependency wiring (DB, clients,
    // worker startup, etc.) goes here.

    // Health probe registration uses two typed funnels (reg.Healthz() has been
    // removed; PROBENAME-SEALED-FUNNEL-01 guards reg.RegisterReadiness as the
    // single write surface):
    // - cell repo readiness: cellgen-generated RegisterReadiness(reg, c.store) (healthz_gen.go)
    // - emitter fail-open probe: shared kernel funnel when the cell holds an outbox.Emitter
    if err := cell.RegisterEmitterHealthProbes(reg, c.emitter); err != nil {
        return err
    }
    return nil
}
```

`cell_gen.go::Init` automatically calls `c.BaseCell.Init(ctx, reg) → c.initInternal(ctx, reg)` and generates RouteGroup registration code from the `// +cell:listener` / `// +slice:route` markers in `cell.go`, as well as Subscribe registration code from `slice.yaml` `contractUsages[role=subscribe]` (see `corecells/configcore/cell_gen.go` for reference).

> Health probes can only be registered through typed funnels: the cell repo probe goes through cellgen's `RegisterReadiness`; the emitter probe goes through `cell.RegisterEmitterHealthProbes(reg, emitter)` (which internally asserts `healthz.ProbeSet` + typed-nil guard, no-op for non-ProbeSet / nil emitters). See `.claude/rules/gocell/observability.md` for details.

### 4. Outbox Injection: Sealed Marker Pattern

Raw infrastructure types (`outbox.Publisher`, `outbox.Writer`, `persistence.TxRunner`) **must not** appear directly in `cell.go` `With*` Option signatures. The reason: these types cannot distinguish between "production-wired" and "demo/test-wired" implementations, allowing callers to pass in arbitrary implementations without going through the composition root, which violates the sealed marker design intent (see ADR `docs/architecture/202605101900-adr-cell-raw-infra-sealed-marker.md §D1`).

The framework provides three sealed marker types, obtainable only through their corresponding `Wrap*ForCell` / `WrapForCell` constructors:

- `outbox.CellPublisher` — wraps `outbox.Publisher`, constructed via `outbox.WrapPublisherForCell(pub)`
- `outbox.CellWriter` — wraps `outbox.Writer`, constructed via `outbox.WrapWriterForCell(w)`
- `persistence.CellTxManager` — wraps `persistence.TxRunner`, constructed via `persistence.WrapForCell(txRunner)`

#### Minimal cell.go Example

```go
// cell.go
package mycell

import (
    "github.com/ghbvf/gocell/framework/kernel/cell"
    "github.com/ghbvf/gocell/framework/kernel/outbox"
    "github.com/ghbvf/gocell/framework/kernel/persistence"
    "github.com/ghbvf/gocell/framework/pkg/validation"
)

type MyCell struct {
    cell.BaseCell
    pendingPublisher outbox.CellPublisher
    pendingWriter    outbox.CellWriter
    txMgr            persistence.CellTxManager
}

// WithOutboxDeps injects sealed outbox dependencies. pub and w must be constructed
// in the composition root via outbox.WrapPublisherForCell / outbox.WrapWriterForCell.
func WithOutboxDeps(p outbox.CellPublisher, w outbox.CellWriter) Option {
    return func(c *MyCell) {
        c.pendingPublisher = p
        c.pendingWriter = w
    }
}

// WithTxManager injects the sealed tx dependency. tx must be constructed in the
// composition root via persistence.WrapForCell. A nil value is silently ignored;
// final nil validation is performed by validateRequired().
// CellTxManager is a sealed interface (cannot be struct-literal constructed); use
// pkg/validation.IsNilInterface for typed-nil detection (kernel/runtime single-source
// helper, see .claude/rules/gocell/runtime-api.md §Option pattern layering — accumulative builder option).
func WithTxManager(tx persistence.CellTxManager) Option {
    return func(c *MyCell) {
        if validation.IsNilInterface(tx) {
            return
        }
        c.txMgr = tx
    }
}
```

#### Composition Root Counterpart

```go
// demo / test mode — construct sealed markers from noop implementations in the composition root.
// DiscardPublisher uses pointer receiver, so pass &outbox.DiscardPublisher{};
// NoopWriter / DemoTxRunner use value receiver, so pass directly by value.
mycell.New(
    mycell.WithOutboxDeps(
        outbox.WrapPublisherForCell(&outbox.DiscardPublisher{}),
        outbox.WrapWriterForCell(outbox.NoopWriter{}),
    ),
    mycell.WithTxManager(persistence.WrapForCell(outbox.DemoTxRunner{})),
)

// production mode — construct sealed markers from real adapters in the composition root
mycell.New(
    mycell.WithOutboxDeps(
        outbox.WrapPublisherForCell(rabbitPub),
        outbox.WrapWriterForCell(pgWriter),
    ),
    mycell.WithTxManager(persistence.WrapForCell(pgTxRunner)),
)
```

In both modes the `cell.go` code is identical; the only switch point is the composition root in `cmd/myapp/main.go` (or `examples/.../main.go`).

Cross-link: Common questions and design rationale in `docs/guides/why-sealed-marker.md`.

ref: `docs/architecture/202605101900-adr-cell-raw-infra-sealed-marker.md §D1`

### 5. Select the Outbox Option Shape for Your Cell's Capabilities

Different cell capabilities require different Option combinations; choosing the wrong shape makes the actual capability invisible in code review:

| Cell capability | Consistency level | Option shape | Examples |
|----------------|------------------|--------------|---------|
| Platform cell (pub + writer + tx) | L1/L2 | `WithOutboxDeps(pub, writer)` + `WithTxManager(tx)` | `corecells/accesscore` `corecells/configcore` `corecells/auditcore` |
| L2 outbox-only (writer + tx only) | L2 OutboxFact | `WithOutboxWriter(writer)` + `WithTxManager(tx)` | `examples/todoorder/cells/ordercell` |
| L4 publish-only (publisher only) | L4 DeviceLatent | `WithDirectPublisher(pub)` | `examples/iotdevice/cells/devicecell` |

The option name suffix corresponds to the actual capability distribution: `WithOutboxDeps` indicates a platform cell holding both publisher and writer; `WithOutboxWriter` indicates an L2 cell that writes to the outbox but does not actively publish; `WithDirectPublisher` indicates an L4 cell that publishes directly without going through the outbox. Choosing the wrong option shape makes capability boundaries invisible in code review, increasing the risk of L2/L4 confusion.

> Note: the table above describes option shapes along the **cell capability dimension** (which outbox paths are present or absent). The corresponding **sealed marker type dimension** (which raw infra maps to which sealed marker / wrap function) is in `.claude/rules/gocell/cell-patterns.md` §"Sealed Marker Wrap Pattern" — the two tables complement each other: this one tells you "which Option to use"; that one tells you "which wrap function backs the Option's parameter type".

### 6. Register HTTP Routes (Optional)

Use `reg.RouteGroup(...)` in `Init` to declare which physical listener each route group belongs to, and use `auth.Mount` inside the `Register` closure to declare authentication semantics (see [runtime-api.md](../../.claude/rules/gocell/runtime-api.md)):

```go
func (c *MyCell) Init(ctx context.Context, reg cell.Registrar) error {
    if err := c.BaseCell.Init(ctx, reg); err != nil {
        return err
    }
    reg.RouteGroup(cell.SingleGroup(cell.PrimaryListener, "/api/v1/my-resource", func(mux cell.RouteMux) error {
        return auth.Mount(mux, auth.Route{
            Contract: wrapper.ContractSpec{
                ID:        "http.mycell.my-resource.get.v1",
                Kind:      "http",
                Transport: "http",
                Method:    "GET",
                Path:      "/api/v1/my-resource/{id}",
            },
            Handler: http.HandlerFunc(c.handler.Get),
            Policy:  auth.Authenticated(),
        })
    }))
    return nil
}
```

#### Listener Routing

The `runtime` layer runs three independent `http.Server` instances:

- **primary** (`:8080` by default) — `/api/v1/*` and all public business routes; JWT AuthMiddleware is wired to this listener via `bootstrap.WithListener(cell.PrimaryListener, ..., []auth.ListenerAuth{...})`.
- **internal** (`127.0.0.1:9090` by default) — only `/internal/v1/*` control-plane routes; service-token / mTLS is wired as a listener-level auth layer via `bootstrap.WithListener(cell.InternalListener, ..., []auth.ListenerAuth{...})`.
- **health** (`127.0.0.1:9091` local/dev by default; `:9091` for production PodIP/Service probes) — only `/healthz`, `/readyz`, `/metrics`.

A Cell calls `reg.RouteGroup(...)` in `Init` for each listener + path prefix combination; bootstrap then mounts each group on the corresponding listener's dedicated router:

```go
func (c *MyCell) Init(ctx context.Context, reg cell.Registrar) error {
    if err := c.BaseCell.Init(ctx, reg); err != nil {
        return err
    }
    reg.RouteGroup(cell.SingleGroup(cell.PrimaryListener, "/api/v1/my-resource", func(mux cell.RouteMux) error {
        return auth.Mount(mux, auth.Route{
            Contract: wrapper.ContractSpec{
                ID:        "http.mycell.my-resource.get.v1",
                Kind:      "http",
                Transport: "http",
                Method:    "GET",
                Path:      "/api/v1/my-resource/{id}",
            },
            Handler: http.HandlerFunc(c.handler.Get),
            Policy:  auth.Authenticated(),
        })
    }))
    reg.RouteGroup(cell.SingleGroup(cell.InternalListener, "/internal/v1/my-resource", func(mux cell.RouteMux) error {
        return auth.Mount(mux, auth.Route{
            Contract: wrapper.ContractSpec{
                ID:        "http.mycell.my-resource.admin-op.v1",
                Kind:      "http",
                Transport: "http",
                Method:    "POST",
                Path:      "/internal/v1/my-resource/admin-op",
            },
            Handler: http.HandlerFunc(c.handler.AdminOp),
            Policy:  auth.AnyRole(auth.RoleInternalAdmin),
        })
    }))
    return nil
}
```

**Constraints**:

- All `/internal/v1/*` routes must be mounted on `cell.InternalListener`; `FinalizeAuth()` validates listener-prefix alignment at startup.
- Nesting `/internal/v1/*` routes inside a `Route` / `Group` / `With` sub-scope is forbidden — it triggers `chiRouterAdapter.guardNestedInternalRegistration` panic (the top-level Router is the sole entry point for internal/external mux splitting).
- `/healthz` / `/readyz` / `/metrics` are only available on the health listener (`cell.HealthListener`); if no health listener is declared, bootstrap phase0 fails fast (since there is no fallback to primary and no opt-in escape hatch).

### 6b. gRPC Per-Method Public Auth (Optional)

A gRPC service is JWT-authed on every method by default (fail-closed). To expose a
specific RPC without a token (e.g. a health probe), declare it in the gRPC contract —
**not** by installing an auth option yourself. The `.proto` remains the single source
of the method set; the contract overlay only **annotates** an existing method.

```yaml
# contract.yaml (kind: grpc)
endpoints:
  grpc:
    codegen: true          # required whenever methods[] is present
    methods:               # SPARSE: list only RPCs that need a non-default flag
      - name: Check        # must match a proto method name (referential integrity is enforced)
        public: true       # the only allowed value (const:true); an absent method stays authed
```

Declaration path (all derived, single-sourced — you write only the contract):

1. contract `endpoints.grpc.methods[].public:true`
2. → cellgen derives `GRPCServiceSpec.PublicMethods []string` (full `/{Service}/{Method}` names, byte-locked by the cellgen golden)
3. → the runtime `ServiceRegistrar` aggregates them (`IsPublicMethod`)
4. → the auth interceptor installs `WithPublicMethod(reg.IsPublicMethod)` for both the unary and stream chains (`authOptionsWithPublicMethods` in `chain.go` — the sole sanctioned installer)

**Compared to HTTP `auth.public`**: an HTTP route declares public access per-route via
the route field (`auth.Route{Public: true}`, §6). gRPC declares it per-method via the
contract overlay because the proto — not the contract — owns the method set, so the
overlay annotates rather than declares. Both are fail-closed: a method/route is authed
unless explicitly marked public.

**Do not** call `WithPublicMethod` or inject a public-method predicate through
`Deps.AuthOptions` in your cell — production `WithPublicMethod` references are funnel-locked
to `chain.go` (`GRPC-PUBLIC-METHOD-WIRING-FUNNEL-01`); the contract overlay is the only
authoring path, and a name absent from the proto fails the codegen referential-integrity
funnel. ABAC `permission`/`resource`/`action` and `internalOnly` are **not** part of this
overlay yet — only `public` is live (the rest are deferred to #2008). See ADR
`docs/architecture/202605260000-adr-grpc-transport-adapter.md` §"Amendment #1675".

### 6c. Business Endpoint Authorization

Business endpoints are permission-gated through the ABAC PDP, not role literals
in handlers. The minimum checklist is:

1. Add a sealed permission accessor in `framework/pkg/authz/permission.go`.
2. Wire the generated handler with `auth.RequirePermission(perm)`.
3. Use `auth.RequirePermissionForResource(pathParam, perm)` for owner/self
   resources so the PDP receives the canonical resource id.
4. Add the corresponding baseline allow rule in the PDP that owns this
   assembly's rules: platform corecells use
   `corecells/accesscore/slices/authorizationdecide/baseline.go`; example,
   external, or self-contained cells keep it in their own `Authorizer()`/PDP.
   Document tenant-policy-only endpoints explicitly.
5. Wire the PDP from the composition root with `bootstrap.WithPrimaryAuthorizer`
   or `bootstrap.PrimaryAuthorizerOption`.
6. Enforce `tenant.RowVisibility` in list/get data PEPs; write endpoints rely on
   typed tenant inputs plus tenant RLS rather than RowScope.
7. Add 403 contract coverage and an e2e/slice assertion for the expected
   permission action.

The full how-to lives in `docs/guides/cell-authz-rowscope-guide.md`.

### 7. Register Event Subscriptions (Optional)

The sole authoritative source for subscriptions is **`slice.yaml` `contractUsages[role=subscribe]`** — cellgen generates the `reg.Subscribe(...)` call into `cell_gen.go` from this declaration. Manually starting goroutines or calling `Subscriber.Subscribe` directly is forbidden; goroutine lifecycle, error convergence, and Setup/Ready phases are all managed by EventRouter.

#### Adding a Subscription: Three Steps

**1. Declare the subscription under `contractUsages` in slice.yaml**:

```yaml
# slice.yaml
contractUsages:
  - contract: event.my.topic.v1
    role: subscribe
    handler: HandleEvent          # required: handler method name on the cell struct field
    # group: my-subgroup          # optional: consumer group; defaults to cellID
verify:
  contract:
    - contract.event.my.topic.v1.subscribe   # hand-written; asserts an executable consumer contract test exists
```

**2. Declare the corresponding field in the cell.go struct** (only needed when creating a new slice; the field pointer type's package name must match the sliceID):

```go
// cell.go
type MyCell struct {
    *cell.BaseCell
    // +slice:route:slice=myslice,subPath=/foo
    mySliceSvc *myslice.Service   // cellgen resolves by "field pointer type package name == sliceID"
}
```

If the same cell struct holds multiple fields from the same package (e.g., the sessionlogout scenario), disambiguate with the `field:` key in slice.yaml:

```yaml
contractUsages:
  - contract: event.role.assigned.v1
    role: subscribe
    handler: HandleRoleAssigned
    field: logoutSvc              # specifies which cell struct field to use
```

**3. Implement the handler method** (`outbox.EntryHandler` signature):

```go
// myslice/service.go
func (s *Service) HandleEvent(ctx context.Context, entry outbox.Entry) outbox.HandleResult {
    // Unmarshal payload, process business logic, return Ack / Requeue / Reject
    return outbox.Ack()
}
```

After running `gocell generate cell`, `cell_gen.go` will automatically include the `reg.Subscribe(...)` call.

The framework wraps ConsumerBase (two-phase Claim/Commit/Release + backoff retry + DLX routing); the business handler only needs to return `outbox.HandleResult`.

EventRouter starts in a four-phase lifecycle after all cells have registered:
1. **Setup**: calls `Subscriber.Setup(sub)` serially; any failure immediately terminates
2. **Subscribe**: starts one goroutine per handler calling `Subscribe(ctx, sub, handler)`
3. **Ready**: waits for all `Subscriber.Ready(sub)` channels to close (30s timeout by default; adjustable via `bootstrap.WithEventRouterReadyTimeout`); any unready subscriptions appear in the error message
4. **Block**: blocks until ctx cancellation or runtime error

### 7b. Register L3 Projections (Optional)

An L3 projection (CQRS read model) is a derived path from `role: subscribe` contractUsage: adding a `projection: <id>` field on the CU causes cellgen to generate `reg.RegisterProjection(...)` instead of `reg.Subscribe(...)`. `<id>` is the snake_case `ProjectionID`; together with `cellID` it forms the checkpoint key `(cell_id, projection_id)`.

#### Minimal slice.yaml Example

```yaml
contractUsages:
  - contract: event.order-created.v1
    role: subscribe
    handler: HandleOrderCreated   # implements cell.ProjectionApply: func(ctx, projection.ProjectionEvent) error
    projection: order_status      # snake_case ProjectionID → cellgen generates reg.RegisterProjection
    projectionSource: outbox      # REQUIRED when projection is set: 'outbox' (this event topic) | 'saga-journal'
    onReset: ResetOrderStatus     # optional: Reset-phase hook during rebuild (cell.ProjectionResetHook)
  - contract: projection.order.status-summary.v1
    role: provide                 # orthogonal role: declares the read/query side; no coupling to projection: field
```

**Key constraints:**

- **Handler signature differs from regular subscriptions**: the handler method must implement `cell.ProjectionApply` = `func(ctx context.Context, event projection.ProjectionEvent) error`, returning `error`, **not** `outbox.HandleResult`. The carrier is the polymorphic `projection.ProjectionEvent` (not the concrete `outbox.Entry`), so the same handler shape works for both `projectionSource: outbox` and `projectionSource: saga-journal`.
- **`projectionSource` is REQUIRED when `projection:` is set**: it selects the input stream. `outbox` consumes the named **event** contract's topic; `saga-journal` consumes the GLOBAL saga journal (the contract must be `kind: saga`; that anchor is a lineage/governance reference, **not** a runtime filter — your Apply handler folds every saga and must filter itself). Omitting it fails `gocell validate`.
- **`onReset` is optional**: omit it if the read model table does not need to be cleared (e.g., for incremental-append semantics); otherwise specify the method name, implementing `cell.ProjectionResetHook` = `func(ctx context.Context) error`. Forbidden with `projectionSource: saga-journal` (that path has no rebuild).
- **`role: provide` is orthogonal**: a `kind: projection` contract's `role: provide` CU declares the read/query side; it has no binding relationship to the `projection:` field; both can exist independently in different slices.
- **A single slice can declare multiple projections**: each CU with a `projection:` field derives an independent `reg.RegisterProjection` (one projectionID + one checkpoint); projectionIDs must be unique within a cell (parser `validateProjectionUniqueness` fail-closed guard).
- **`cell.yaml` must declare `consistencyLevel: L3`** (unidirectional implication: using projection ⟹ L3; see `.claude/rules/gocell/saga.md` §"Key Clarification: L3 and Saga"). The cell-level declaration is still a convention enforced by `validateProjectionUniqueness`. Note: a `kind: projection` **contract's** own `consistencyLevel ≥ L3` is enforced at compile time by contractgen's codegen funnel (the generated `types_gen.go` carries `const _ = uint(cellvocab.<level> - cellvocab.L3)`; a level below L3 causes a compile-time overflow); this is a contract-level Hard constraint, orthogonal to the cell-level convention here.

#### cellgen Derived Behaviour

After running `gocell generate cell`, `cell_gen.go` (DO-NOT-EDIT) automatically contains:

```go
// cell_gen.go (DO NOT EDIT) — cellgen derives from slice.yaml contractUsages[projection=order_status]
import ordercreated "github.com/ghbvf/gocell/generated/contracts/event/order-created/v1"
// ...
if err := reg.RegisterProjection(ordercreated.NewProjectionRequest(
    c.orderProj.HandleOrderCreated, "order_status", "ordercell", "orderprojection",
    c.orderProj.ResetOrderStatus, // onReset; nil when not declared
)); err != nil {
    return fmt.Errorf("ordercell: projection order_status: %w", err)
}
```

The `NewProjectionRequest` signature is `(apply cell.ProjectionApply, projectionID, cellID, sliceID string, onReset cell.ProjectionResetHook)`, derived by contractgen from `event.order-created.v1`'s contract.yaml into `generated/contracts/event/order-created/v1/projection_gen.go`.

Handler implementation example (note the `error` return, not `outbox.HandleResult`):

```go
// <slice>/service.go — ProjectionApply signature
func (s *Service) HandleOrderCreated(ctx context.Context, event projection.ProjectionEvent) error {
    // tx is passed through ctx (ambient-tx, see ADR Q1/Q2); apply and checkpoint SaveOffset
    // commit in the same CellTx. event.Payload() / event.EventID() / event.Stream()
    // expose the polymorphic carrier (outbox.Entry and the saga-journal carrier both
    // implement projection.ProjectionEvent).
    return s.store.Apply(ctx, event)
}
```

Bootstrap drains `RegistrySnapshot.Projections` into one `projection.Coordinator` per projection; the checkpoint uses ambient-tx (`SaveOffset` and the business apply commit in the same `CellTx`) for exactly-once semantics.

See ADR `docs/architecture/202605261620-adr-cqrs-projection-lifecycle-harness.md` (decisions Q1–Q3 + §6 threat matrix).

> Reference implementation: `examples/todoorder/cells/ordercell/slices/orderprojection` (L3 projection harness canonical reference, L3-EXAMPLE-PROJECTION-01).

## Schema Evolution

`contracts/{kind}/{domain}/v{N}/*.schema.json` is the sole cross-cell contract. Schema evolution follows three policies depending on direction (see [ADR-202605031600](../architecture/202605031600-adr-v1-schema-evolution.md) and [api-versioning.md](../../.claude/rules/gocell/api-versioning.md)):

| Policy | Applicable schema | Constraint | Guard |
|--------|------------------|------------|-------|
| **strict (request)** | `request.schema.json`, `error-response-v1.schema.json` | Must declare `additionalProperties: false` (including nested) | FMT-20 + `verify-schema-policy.sh` |
| **lenient (response/event)** | `response.schema.json`, `payload.schema.json`, `headers.schema.json` | **Forbidden** to declare `additionalProperties: false` (allows v1 to add optional fields without breaking clients/consumers) | `verify-schema-policy.sh --check` |
| **metaonly (allowlist)** | Metadata-only event payload (carrier holds only identifiers, no state, e.g. `event.config.entry-upserted.v1`) | Must declare `unevaluatedProperties: false`; new fields must be explicitly added to `properties` (prevents state fields from being accidentally included) | `verify-schema-policy.sh --check` |

### Workflow for Adding New Fields

| Scenario | Steps |
|----------|-------|
| Add an optional field to a v1 response/event payload | 1) Update schema `properties`; 2) Update typed struct + JSON tag; 3) Contract test passes; CI auto-validates |
| Add an optional field to a v1 request | Same as above; schema remains strict (FMT-20), so `properties` list must be updated |
| Add an identifier field to a metadata-only event | Same as above; `unevaluatedProperties: false` requires `properties` to list all valid fields explicitly |
| Delete a field / change a field type / change field semantics | Must v2 — not within v1 evolution scope |

### Check Commands


### Using Contract Tests

`tests/contracttest` provides two symmetric APIs: `Validate*` for compliance validation, `MustReject*` for negative assertions. Under a lenient schema, `MustReject*` only catches non-additive violations such as `required`/`type`/`pattern`; to assert "extra fields are rejected", the schema must be metaonly or strict.

```go
c := contracttest.LoadByID(t, root, "event.config.entry-upserted.v1")
c.ValidatePayload(t, payload)                                          // positive case
c.MustRejectPayload(t, []byte(`{"key":"k"}`))                         // missing required → rejected
c.MustRejectPayload(t, []byte(`{"key":"k","version":1,"actorId":"a","value":"x"}`))
                                                                       // metaonly: extra "value" → rejected
```

## Slice Dependency Injection Pattern

GoCell uses **construction-time injection**: all dependencies are passed through Option functions at `New*Cell()` time, and the Cell distributes them to each Slice in `Init()`.

```go
// Option pattern
type Option func(*MyCell)

func WithMyRepo(r ports.MyRepository) Option {
    return func(c *MyCell) { c.repo = r }
}

// codegen pattern: Init is generated in cell_gen.go.
// Business-specific initialisation lives in the hand-written initInternal hook.
//
// cell_gen.go (generated by `gocell generate cell`):
//
//   func (c *MyCell) Init(ctx context.Context, reg cell.Registrar) error {
//       if err := c.BaseCell.Init(ctx, reg); err != nil {
//           return err
//       }
//       return c.initInternal(ctx, reg)
//   }
//
// cell.go (hand-written initInternal):
func (c *MyCell) initInternal(ctx context.Context, reg cell.Registrar) error {
    svc := myslice.NewService(c.repo, c.logger)
    c.handler = myslice.NewHandler(svc)
    // slice.yaml is the SoR; gocell generate cell emits slice_gen.go with
    // SliceMetadata(), which MustNewBaseSliceFromMeta consumes via the typed funnel.
    // Direct cell.NewBaseSlice literals and metadata.SliceMeta{} hand-written
    // literals are forbidden (BASESLICE-CTOR-FUNNEL-01).
    c.AddSlice(cell.MustNewBaseSliceFromMeta(myslicepkg.SliceMetadata()))
    return nil
}
```

For development and testing, inject dependencies explicitly (`WithInMemoryDefaults()` has been removed; explicit wiring is required):

```go
// Explicitly construct in-memory dependencies and inject them in test/dev mode
func buildAccessCoreMemOptions(tb testing.TB, clk clock.Clock) []accesscore.Option {
    tb.Helper()
    userStore := mem.NewStore(clk)
    // Use sessiontest.Protocol() instead of session.NewProtocol directly:
    // session.NewProtocol is guarded by SESSION-PROTOCOL-COMPOSITION-ROOT-01
    // (only cmd/* and runtime/auth/session/* may call it).
    sessionProto := sessiontest.Protocol()
    sessionStore, err := session.NewMemStore(sessionProto, clk)
    if err != nil {
        tb.Fatalf("session.NewMemStore: %v", err)
    }
    refreshStore, err := refreshmem.New(accesscore.DefaultRefreshPolicy(), clk, nil)
    if err != nil {
        tb.Fatalf("refreshmem.New: %v", err)
    }
    return []accesscore.Option{
        accesscore.WithUserRepository(userStore.UserRepository()),
        accesscore.WithRoleRepository(userStore.RoleRepository()),
        accesscore.WithSessionStore(sessionStore),
        accesscore.WithRefreshStore(refreshStore),
    }
}
```

`session.MustNewProtocol` has been removed. In test helper functions, obtain the standard test Protocol via `sessiontest.Protocol()` (in package `runtime/auth/session/sessiontest`) rather than calling `session.NewProtocol` directly, to avoid scattering duplicate options across helpers. `session.NewProtocol` is still guarded by the SESSION-PROTOCOL-COMPOSITION-ROOT-01 archtest (only `cmd/*` or `runtime/auth/session/*` may call it).

## Testing

Use table-driven tests; coverage must be ≥ 90% for the `kernel/` layer and ≥ 80% for other layers.

```go
func TestMyCell_Lifecycle(t *testing.T) {
    c := NewMyCell(clock.Real(), WithInMemoryDefaults()) // clock is the first required positional parameter; WithClock option is removed.
    ctx := context.Background()
    rec := cell.NewRegistryRecorder(map[string]any{}, outbox.DurabilityDemo)

    require.NoError(t, c.Init(ctx, rec))
    snap := rec.Snapshot()
    // Use snap.RouteGroups / snap.Subscriptions / snap.HealthCheckers etc.
    // to assert the capabilities declared by the cell
    require.NotEmpty(t, snap.HealthCheckers)

    require.NoError(t, c.Start(ctx))
    assert.Equal(t, "healthy", c.Health().Status)
    require.NoError(t, c.Stop(ctx))
}
```

## Integration Testing

Integration tests verify adapter behaviour against real infrastructure. They use the `//go:build integration` build tag and are excluded from the default `go test ./...`.

### Writing Integration Tests for Your Cell

1. Create `integration_test.go` in your Cell or adapter package.
2. Add `//go:build integration` as the first line.
3. Start required infrastructure with testcontainers and call `testutil.RequireDocker(t)` before the first container start.
4. Pass container-returned DSNs directly into the adapter or Cell under test; do not skip on missing external DSN environment variables.
5. Each test should be self-contained: create its own resources, run assertions, then clean up.

```go
//go:build integration

package mycell

import (
    "context"
    "testing"

    "github.com/ghbvf/gocell/tests/testutil"
    tcpostgres "github.com/testcontainers/testcontainers-go/modules/postgres"
)

func TestIntegration_MyCellSmoke(t *testing.T) {
    testutil.RequireDocker(t)

    ctx := context.Background()
    container, err := tcpostgres.Run(ctx, testutil.PostgresImage)
    require.NoError(t, err)
    t.Cleanup(func() { _ = container.Terminate(context.Background()) })

    dsn, err := container.ConnectionString(ctx, "sslmode=disable")
    require.NoError(t, err)

    repo := newPostgresRepo(dsn)
    c := NewMyCell(
        clock.Real(), // clock is the first required positional parameter; WithClock option is removed.
        WithPostgresRepo(repo),
    )
    rec := cell.NewRegistryRecorder(map[string]any{}, outbox.DurabilityDemo)

    require.NoError(t, c.Init(ctx, rec))
    require.NoError(t, c.Start(ctx))
    defer c.Stop(ctx)

    // Exercise real adapter paths
    // ...
}
```

```bash
GOCELL_TEST_DOCKER_REQUIRED=1 go test -tags integration ./adapters/postgres/... -count=1 -v
GOCELL_TEST_DOCKER_REQUIRED=1 go test -tags integration ./tests/integration/... -count=1 -v
```

## Joining an Assembly

The workflow for wiring a new cell into an assembly after creation:

### Steps

1. **Add the cell to assembly.yaml**: append the new cell ID to the `cells:` list in `assemblies/<assemblyID>/assembly.yaml`
2. **Add a composition module**: implement the public `composition.CellModule` interface (`Provide(ctx, shared) (cell.Cell, []bootstrap.Option, []lifecycle.ManagedResource, error)` — the `ModuleExports` input/return value was removed; cross-cell communication uses event contracts; the signature is frozen by the `MODULE-PROVIDE-NO-VALUE-HANDOFF-01` archtest). Platform cells live in `cellmodules/<cell>/module.go` (reference: `cellmodules/accesscore/module.go`, assembled via `composition.New().With(...).Build(...)`); example assembly cells live in `cmd/<assemblyID>/<cell>_module.go` or `examples/<assemblyID>/`
3. **Run codegen**: `gocell generate assembly --id=<assemblyID>` derives the new `cmd/<assemblyID>/modules_gen.go`
4. **CI drift gate**: `gocell verify codegen-assembly` automatically validates `modules_gen.go` ↔ `assembly.yaml` consistency

### Naming Convention

The shape of `modules_gen.go` is determined by `assembly.yaml`'s `build.compositionAPI` setting (template selection in `kernel/assembly/generator.go`):

- **`compositionAPI: true` (platform assembly, e.g. corebundle)**: `generatedCellModules()` returns `[]composition.CellModule`; each element calls `cellmodules/<cell>.Module()` — platform cell module wiring lives in the public `Module() composition.CellModule` factory exposed by `cellmodules/<cell>/module.go`, assembled via `composition.New().With(...).Build(...)`. **This path has no local `{GoStructName}Module` factory type**.
- **`compositionAPI: false` (default, example assemblies like todoorder / iotdevice)**: `generatedCellModules()` returns local `[]CellModule`; each element is a `{cell.GoStructName}Module{}` literal (e.g., cell.GoStructName=`OrderCell` → `OrderCellModule{}`). `<cell>_module.go` must define the struct with this exact name.

Archtest **ASSEMBLY-CELLMODULE-TYPE-04** statically guards that when an assembly's entrypoint directory (`cmd/{id}/` or `examples/{id}/`, derived from `asm.Build.Entrypoint` metadata) contains `modules_gen.go`, it must declare a local `CellModule` type (legacy form) **or** reference `composition.CellModule` (compositionAPI form) — either one is sufficient.
Archtest **ASSEMBLY-MODULES-GEN-01** guards the generated marker.
Archtest **ASSEMBLY-MODULES-SWITCH-FORBIDDEN-02** guards that direct files in the assembly composition root (`cmd/{id}/` or `examples/{id}/`) do not degrade to hand-written cell-ID switches; the scan scope is limited to `.go` files in the entrypoint directory and does not recurse into subdirectories (e.g., `examples/{id}/cells/`).

### Derived Fields

`assembly.yaml` requires only `id` + `cells` + `owner`; all other fields are derived from cell metadata:

| Field | Derivation rule | Explicit override |
|-------|----------------|------------------|
| `build.entrypoint` | `cmd/{id}/main.go` (for `assemblies/{id}/` assembly) or `examples/{id}/main.go` (for `examples/{id}/` assembly) — see `kernel/metadata/assembly_derive.go::deriveAssembly` | ✓ |
| `build.binary` | the assembly id itself | ✓ |
| `build.deployTemplate` | defaults to `k8s` (schema enum: k8s/compose/binary) | ✓ |
| `maxConsistencyLevel` | `max(cells[].consistencyLevel)` | ✗ derived read-only; yaml declaring this key is rejected (KnownFields + schema additionalProperties:false double guard) |

See ADR `docs/architecture/202605061800-adr-assembly-yaml-minimal-derivation.md`.

## External Repository Mode

GoCell supports three Cell development modes:

| Mode | Repository shape | Configuration |
|------|-----------------|--------------|
| **Monorepo** (gocell itself) | Same `go.mod` | Default conventional layout (no `.gocell/manifest.yaml`) |
| **Operator-SDK** | External repo `go get github.com/ghbvf/gocell/framework` | Place `.gocell/manifest.yaml` at the repo root with 1 module entry |
| **Workspace** | `go.work` aggregating gocell + multiple cell modules | Place `.gocell/manifest.yaml` at the workspace root with multiple module entries |

### Conventional Layout (Default)

When `.gocell/manifest.yaml` is absent, Locator uses conventional 5-pattern detection:

```
<root>/
├── cells/<cellID>/cell.yaml
├── cells/<cellID>/slices/<sliceID>/slice.yaml
├── contracts/<kind>/.../v<N>/contract.yaml
├── journeys/J-<id>.yaml
├── assemblies/<id>/assembly.yaml
├── journeys/status-board.yaml     # workspace-level singleton
└── actors.yaml                    # workspace-level singleton
```

### Manifest Layout

Place `<root>/.gocell/manifest.yaml`:

```yaml
version: v1
modules:
  - path: .                            # required, relative to manifest dir
    # includes: omit = use default 5-pattern
    excludes: ["generated/**", "vendor/**"]
```

#### Workspace Multi-Module

```yaml
version: v1
modules:
  - path: .                            # workspace root, holds actors / status-board singletons
    includes:
      cells: ["cells/*/cell.yaml"]
      slices: ["cells/*/slices/*/slice.yaml"]
      contracts: ["contracts/**/contract.yaml"]
      journeys: ["journeys/J-*.yaml"]
      assemblies: ["assemblies/*/assembly.yaml"]
      actors: "actors.yaml"
      statusBoard: "journeys/status-board.yaml"
  - path: ./vendor-cells/payment       # sub-module, aggregated by go.work `use ./vendor-cells/payment`
    # includes: same structure as above; leave actors / statusBoard empty (singleton only declarable in modules[0])
```

`actors.yaml` and `journeys/status-board.yaml` are workspace-level singletons: **they can only be declared in modules[0]**; declaring them in multiple modules is rejected by Locator (fail-fast).

### CLI Flag

`gocell validate` and `gocell check ...` support explicit layout overrides:

```bash
# auto-detect (default)
gocell validate

# force manifest mode
gocell validate --layout=manifest

# explicit manifest path
gocell validate --layout=manifest --manifest=./config/.gocell/manifest.yaml

# force conventional (CI safeguard against accidental manifest)
gocell validate --layout=conventional
```

The other CLI command families (`generate`, `verify`, `export`, `scaffold`, `graph`, and `check`) work via auto-detect automatically — if `<root>/.gocell/manifest.yaml` exists it is used, with no explicit flag required. Assembly and codegen operations are subcommands inside those families, such as `gocell scaffold assembly`, `gocell generate assembly`, and `gocell verify codegen-assembly`.

> **Exception**: `gocell check unconditional-skip` does not use `metadata.Locator` (it scans Go code directly via `go/packages` for static analysis); its behaviour is determined entirely by Go package paths and is unaffected by manifest configuration.

### slice belongsToCell in Manifest Mode

In conventional layout, `slice.yaml::belongsToCell` can be omitted; it is auto-derived from `<X>` in the path `cells/<X>/slices/<Y>/slice.yaml`. In manifest mode, if a slice's `includes` pattern does not follow the `cells/<X>/slices/<Y>/` structure, **Locator cannot derive the cellID and `slice.yaml` must explicitly declare `belongsToCell`**, otherwise parsing fails.
