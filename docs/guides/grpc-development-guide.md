# gRPC Development Guide

This guide covers writing a gRPC handler in a GoCell cell, handling errors, understanding
the interceptor chain, and optionally enabling rate-limiting and circuit-breaking.

The iotdevice example (`examples/iotdevice/cells/devicecell/`) is the canonical reference
implementation; all steps here are verified against it.

## Writing Your First gRPC Handler

### 1. Declare the contract

Create `contracts/grpc/<domain>/<version>/contract.yaml`:

```yaml
id: grpc.todoorder.command.v1
kind: grpc
ownerCell: todoorder
consistencyLevel: L1
lifecycle: active
endpoints:
  server: todoorder
  clients: []
  grpc:
    service: todoorder.command.v1.OrderCommandService
    proto: contracts/grpc/todoorder/command/v1/order_command.proto
    methods:
      - name: CreateOrder
        permission: order:write      # non-public RPCs must declare a permission
```

The `endpoints.grpc` block (parallel to `endpoints.http`) is the only required gRPC
transport config. The `methods[]` overlay provides per-RPC auth annotation; every
non-public RPC must appear here (completeness pre-pass enforced at codegen).

### 2. Write the proto

```protobuf
syntax = "proto3";
package todoorder.command.v1;
option go_package = "github.com/ghbvf/gocell/generated/contracts/grpc/todoorder/command/v1;orderv1";

service OrderCommandService {
  rpc CreateOrder(CreateOrderRequest) returns (CreateOrderResponse) {}
}

message CreateOrderRequest { string customer_id = 1; }
message CreateOrderResponse { string order_id = 1; }
```

### 3. Generate

```bash
make proto-gen     # buf generates .pb.go + _grpc.pb.go under generated/contracts/grpc/
gocell generate    # contractgen emits NOTHING for kind=grpc (#1688);
                   # cellgen emits cell_gen.go with reg.GRPCService(...)
```

buf's generated `pb.<Svc>Server` interface is the server contract — GoCell does not emit
a parallel Go interface for gRPC (#1688). Your handler implements the buf interface
directly (idiomatic grpc-go / Kratos).

### 4. Implement the handler

```go
package ordercommand

import (
    "context"

    orderv1 "github.com/ghbvf/gocell/generated/contracts/grpc/todoorder/command/v1"
    "github.com/ghbvf/gocell/framework/pkg/errcode"
)

// Server implements orderv1.OrderCommandServiceServer (generated by buf).
type Server struct {
    orderv1.UnimplementedOrderCommandServiceServer // embed by value — forward-compat
    repo domain.OrderRepository `gocell:"required"`
}

func (s *Server) CreateOrder(
    ctx context.Context,
    req *orderv1.CreateOrderRequest,
) (*orderv1.CreateOrderResponse, error) {
    if req.GetCustomerId() == "" {
        return nil, errcode.New(errcode.KindInvalid, errcode.ErrValidationFailed,
            "customer_id is required",
            errcode.WithDetails(errcode.PublicString("field", "customer_id")))
    }
    // ... business logic ...
    return &orderv1.CreateOrderResponse{OrderId: order.ID}, nil
}
```

Return shapes: `(*pb.Response, nil)` for success; `(nil, error)` for failure. Return a
plain `*errcode.Error` — the `ErrcodeMap` interceptor (PR-12) converts it to the correct
`codes.Code` before the response leaves the server. No grpc-specific error construction
in the handler.

### 5. Register via the cell struct

```go
// cells/todoorder/cell.go
type Cell struct {
    cell.BaseCell
    ordercommand *ordercommand.Server  // cellgen matches: pointer-type package == slice id
}
```

`cell_gen.go` emits `reg.GRPCService(...)` — do not hand-write this call.

## Error Handling

Return a plain `*errcode.Error` from your handler. The `ErrcodeMap` interceptor sits just
outside `Recovery` in the chain and converts it to the appropriate gRPC status code.

### errcode.Kind → codes.Code mapping

| errcode.Kind | HTTP equiv | grpc codes.Code |
|---|---|---|
| KindInternal | 500 | Internal |
| KindInvalid | 400 | InvalidArgument |
| KindUnauthenticated | 401 | Unauthenticated |
| KindPermissionDenied | 403 | PermissionDenied |
| KindNotFound | 404 | NotFound |
| KindConflict | 409 | Aborted |
| KindUnprocessable | 422 | InvalidArgument |
| KindGone | 410 | NotFound |
| KindPayloadTooLarge | 413 | ResourceExhausted |
| KindRateLimited | 429 | ResourceExhausted |
| KindClientClosed | 499 | Canceled |
| KindDeadlineExceeded | 504 | DeadlineExceeded |
| KindUnavailable | 503 | Unavailable |
| KindNotImplemented | 501 | Unimplemented |
| (unknown / default) | — | Internal (fail-closed) |

The mapping is documented in `docs/architecture/202605260100-adr-grpc-errcode-mapping.md`.
It is exhaustively enforced by archtest `GRPC-ERRCODE-MAPPING-01` — a future `errcode.Kind`
that is not added to the table fails CI.

### 4xx vs 5xx redaction

The same PII discipline as HTTP applies:

- **4xx-equivalent (`Kind.IsClient()` true)**: the `errcode.Error.Message` is forwarded
  on the wire. **Note**: `WithDetails(PublicString/PublicInt/...)` public attrs are
  intentionally NOT carried in `google.rpc.Status.Details` today — only the message is
  forwarded (fail-safe default). 4xx-details parity with HTTP is tracked in **#2482**.
- **5xx-equivalent (`!Kind.IsClient()`)**: the wire message is replaced with a generic
  constant; public attrs are stripped. `WithInternal(InternalAttr)` data goes only to
  server-side `slog`, never to the wire.

Handlers must not construct the gRPC status themselves — that would bypass redaction.
Do NOT implement `GRPCStatus()` on `*errcode.Error` for the same reason (it bypasses
this interceptor's 5xx redaction).

**KindGone retry semantics**: `KindGone` maps to `codes.NotFound`. Consumers MUST NOT
infer retryability from `codes.NotFound` alone — it covers both "never existed" and
"permanently gone". Handlers that mean "permanently gone" must signal this via an
app-level field or event, not solely via the gRPC code.

### Auth / authz denial

Denials from the auth interceptor carry a `google.rpc.ErrorInfo` detail with a sealed
`Reason` code and `Domain="gocell.authz.grpc"`. The closed set of reason values is:

| Reason | Meaning |
|---|---|
| `INVALID_AUTH_METADATA` | Missing or malformed authorization header |
| `AUTHENTICATION_REQUIRED` | No bearer token present |
| `INVALID_TOKEN` | Token failed cryptographic / expiry verification |
| `AUTHN_SERVICE_UNAVAILABLE` | Token verifier (session store / key provider) unavailable |
| `PASSWORD_RESET_REQUIRED` | Token is valid but the caller must reset their password |
| `NO_PERMISSION_MAPPING` | Method has no permission overlay (config / codegen error) |
| `AUTHZ_NOT_WIRED` | No Authorizer configured in the composition root |
| `INSUFFICIENT_PERMISSIONS` | PDP denied the request (no matching allow rule) |
| `AUTHORIZATION_DENIED` | PDP explicit deny (forbid rule or default-deny) |
| `OBLIGATIONS_UNSUPPORTED` | PDP allow carries obligations the gate cannot enforce |
| `PDP_UNAVAILABLE` | Policy store unavailable (fail-closed) |
| `RESOURCE_UNRESOLVED` | Owner-scoped method's resource field extraction failed structurally |

The `Metadata` map carries only `method` and `permission` (non-PII) — never subject,
token, or resource value.

## Interceptor Chain Order

After PR-12, the full chain order is:

**Unary RPC:**
```
RequestID → CellAttribution → Tracing → AccessLog → Metrics
  → RateLimit → CircuitBreaker → Auth → ErrcodeMap → Recovery → handler
```

**Server-streaming RPC:**
```
RequestID → CellAttribution → Tracing → AccessLog → Metrics
  → RateLimit → CircuitBreaker → Auth → Drain → ErrcodeMap → Recovery → handler
```

What each interceptor does:

| Interceptor | Purpose |
|---|---|
| RequestID | Assigns a correlation ID; propagates via context and response trailer. |
| CellAttribution | Resolves the gRPC full method to a cell ID for metrics labels. Must run before Metrics. |
| Tracing | Starts an OTEL span; injects trace context into child calls. |
| AccessLog | Emits a structured access-log entry (method, code, latency, cell). |
| Metrics | Records `grpc_server_requests_total` and latency histograms with `cell` label. |
| RateLimit | Opt-in. Deny → `codes.ResourceExhausted`. Key = peer address. |
| CircuitBreaker | Opt-in. Open → `codes.Unavailable`. Counts only server-failure codes as failures. |
| Auth | Validates the JWT; resolves the principal; applies PDP gate (unary) or gates stream open (streaming). |
| Drain | Stream-only. Rejects new streams during graceful shutdown. |
| ErrcodeMap | Converts `*errcode.Error` → gRPC status with the mapping table. Applies 5xx redaction. |
| Recovery | Innermost panic backstop. Recovered panic → `codes.Internal` + registered reason. |

The chain is minted by the single public funnel `interceptor.NewServerInterceptors(deps)`.
Composition roots must not build a partial chain — the funnel enforces chain completeness
(archtests `GRPC-WIRING-BUNDLE-CALLER-01` + `GRPC-WIRING-REGISTRAR-MINT-FUNNEL-01`, Hard).

## Enabling Rate-Limit and Circuit-Breaker

Both interceptors are **opt-in** via `interceptor.Deps`. When a field is nil the
interceptor is a no-op passthrough.

```go
// In the composition root (e.g. examples/iotdevice/run.go):
deps := interceptor.Deps{
    // Required fields (always populated by NewServerInterceptors):
    //   Tracer, Collector, Clock, Verifier, Authorizer, MetricsProvider, CellIDClosedSet, ...

    // Optional protection chain:
    RateLimiter: myRateLimiter,   // implements interceptor.RateLimiter
    Allower:     myBreaker,       // implements interceptor.Allower
}
interceptors := interceptor.NewServerInterceptors(deps)
```

The interfaces:

```go
// RateLimiter.Allow returns true to pass, false to deny (→ codes.ResourceExhausted).
// key is the gRPC peer address (port stripped).
type RateLimiter interface {
    Allow(key string) bool
}

// Allower.Allow returns (true, done) to pass, (false, nil) to reject (→ codes.Unavailable).
// done(err) is called after the call completes; err=nil for success or client error.
// A non-nil done MUST be returned whenever allowed==true; nil done triggers fail-open + log.
type Allower interface {
    Allow() (allowed bool, done func(err error))
}
```

**RateLimit and CircuitBreaker run BEFORE Auth** in the chain — unauthenticated requests
also consume rate-limit / circuit-breaker budget (deliberate, symmetric with HTTP middleware
ordering). Set lenient burst limits to avoid starving legitimate principals.

**Shared instance**: the concrete limiter/breaker can be the same instance serving both
HTTP middleware and gRPC interceptors — the interfaces are transport-agnostic. Wire once
in the composition root; pass the same value to both `runtime/http` middleware and
`interceptor.Deps`.

**Circuit-breaker failure set**: the breaker counts these codes as server failures:
`{Internal, Unknown, Unavailable, DataLoss, DeadlineExceeded}`. Excluded:
`Unimplemented` (permanent contract gap, not a runtime fault) and `ResourceExhausted`
(overload/rate-limit, a 4xx-family semantic). This mirrors HTTP's 5xx-only convention.

**Streaming**: the breaker gates stream establishment. An open circuit returns
`codes.Unavailable` before the handler runs. `done(err)` is called at stream close.

## Auth: Public and Owner-Scoped RPCs

### Public RPC (no JWT required)

Declare `public: true` in the methods overlay (mutually exclusive with `permission`):

```yaml
endpoints:
  grpc:
    methods:
      - name: GetServerVersion
        public: true
```

### Owner-scoped RPC (device watches its own queue)

Declare `permission` + `resource` (the proto request-message field whose value becomes
the PDP resource):

```yaml
methods:
  - name: WatchCommands
    permission: device:consume
    resource: device_id   # proto snake_case field name
```

For unary RPCs the resource is extracted at interceptor entry; for server-streaming RPCs
the full permission gate is deferred to the first `RecvMsg` (when the request message is
available). Structural extraction failure → deny (`codes.PermissionDenied`), never a
fallback to the full method name.

### Password-reset-exempt RPC

A method that a password-reset-required user must reach (e.g., change-password):

```yaml
methods:
  - name: ChangePassword
    permission: user:write       # required — exempt methods are still ABAC-gated
    passwordResetExempt: true    # mutually exclusive with public
```

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `gocell generate cell` reports "no cell.go struct field for slice" | Cell struct missing a `*<sliceID>.T` pointer field | Add `*ordercommand.Server`; the pointer-type package must equal the slice id |
| Handler does not compile with `pb.Register<Svc>Server` | Handler missing `pb.Unimplemented<Svc>Server` embed | Embed `<pb>.Unimplemented<Svc>Server` by value in the handler struct |
| `gocell validate` rejects contract | Missing required fields | Ensure `grpc.service` and `grpc.proto` are set; `method`/`streamingType` were removed in #1655 |
| `*errcode.Error` surfaces as `codes.Unknown` | Running a pre-PR-12 build | Upgrade to PR-12+; the `ErrcodeMap` interceptor is the fix |
| Handler receives auth-related panic at startup | `MethodPermissions` entries with no Authorizer wired | The registrar fail-fasts at phase7b drain — wire `interceptor.Deps.Authorizer` in the composition root |
