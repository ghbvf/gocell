# Contract: webhook (kind)

**Status**: Draft (PR-2 落地)
**Owner**: kernel/webhook
**Version**: v1

## 概述

`webhook` 是 GoCell 跨 Cell 边界的契约 kind 之一，与现有 `event` / `sync` / `command` / `query` 并列。它声明了一个 webhook 端点的不可变约束：

- 方向（inbound 接收 / outbound 推送）
- 关联的 source/target 标识
- 签名算法与版本
- 端点路径模式（inbound）或 URL 选择器名（outbound）
- 业务负载 schema（JSON Schema 引用）

业务 Cell 在 slice.yaml 通过 `contractUsages[role=webhook-receive]` 或 `[role=webhook-dispatch]` 引用契约，由 cellgen 派生注册代码。

## 文件位置

```
contracts/webhook/{domain-path}/{version}/contract.yaml
contracts/webhook/{domain-path}/{version}/payload.schema.json
```

例：
```
contracts/webhook/stripe/payment-events/v1/contract.yaml
contracts/webhook/stripe/payment-events/v1/payload.schema.json
```

## contract.yaml schema 草图

```yaml
id: webhook.stripe.payment-events.v1
kind: webhook
direction: inbound                 # inbound | outbound
version: v1
owner: payments
description: Stripe payment events webhook

signature:
  algorithm: hmac-sha256           # 初版唯一值
  toleranceSeconds: 300            # 双向（拒 too old + too new）
  deliveryIDHeader: X-Stripe-Delivery-Id  # 入站取 header；出站派生
  timestampHeader: X-Stripe-Timestamp     # 入站取 header；出站派生
  signatureHeader: X-Stripe-Signature     # 入站取 header；出站派生
  signedStringForm: "{deliveryID}.{timestamp}.{body}"   # 锁形态

endpoints:
  inbound:
    pathPattern: /api/webhooks/stripe/payment-events
    sourceID: stripe
  # outbound 不写 endpoints；URL 由业务侧 URLSelector 给出

payload:
  schemaRef: ./payload.schema.json
  contentType: application/json
  maxBodyBytes: 1048576           # 1 MB

# 派生字段（不可手写，cellgen/contractgen 写入）
receivers: [<cell-ids>]            # 入站：派生自 slice.yaml CU
dispatchers: [<cell-ids>]          # 出站：派生自 slice.yaml CU
```

## slice.yaml contractUsages 扩展

```yaml
# inbound 角色
contractUsages:
  - contract: webhook.stripe.payment-events.v1
    role: webhook-receive          # 新 role
    handler: HandleStripeEvent     # 必填，业务方法名
    sourceID: stripe               # 必填，密钥隔离键（与 contract.endpoints.inbound.sourceID 一致）

# outbound 角色
contractUsages:
  - contract: webhook.shopify.orders.v1
    role: webhook-dispatch         # 新 role
    targetSelector: ShopifyTarget  # 必填，target URL 选择器方法名
    sourceID: shopify              # 必填，签名密钥来源
```

## 派生形态（cellgen 生成 cell_gen.go）

```go
// Auto-generated by cellgen — DO NOT EDIT
func (c *MyCell) Init(ctx context.Context, reg cell.Registrar) error {
    if err := c.BaseCell.Init(ctx, reg); err != nil {
        return err
    }
    // From slice.yaml contractUsages[role=webhook-receive]
    if err := reg.RegisterWebhookReceiver(webhook.ReceiverSpec{
        ContractID: "webhook.stripe.payment-events.v1",
        SourceID:   "stripe",
        CellID:     c.ID(),
    }, c.svc.HandleStripeEvent); err != nil {
        return err
    }
    // From slice.yaml contractUsages[role=webhook-dispatch]
    return reg.RegisterWebhookDispatch(webhook.DispatchSpec{
        ContractID: "webhook.shopify.orders.v1",
        SourceID:   "shopify",
        CellID:     c.ID(),
    }, c.svc.ShopifyTarget)
}
```

## 静态守卫

| invariant | 守 |
|----------|----|
| CONTRACT-YAML-WEBHOOK-FIELDS-FROZEN | contract.yaml `receivers` / `dispatchers` 字段 `yaml:"-"`（派生不可手写） |
| WEBHOOK-MARKER-RETIRED | 任何 `// +webhook:receive` 或 `// +webhook:dispatch` 注释 marker 都是编译期错误（强制走 slice.yaml 单源） |
| WEBHOOK-CELL-ID-POSITIONAL | RegisterWebhookReceiver/Dispatch 第 3 个位置参数必传 cellID（typed string，不可空） |

## 演化策略（对齐 .claude/rules/gocell/api-versioning.md）

- v1.0 GA 前：契约直接演化，无 v2 升级，无 deprecation 期
- v1.0 GA 后：新增 optional 字段在 v1 下加；删除/重命名/类型变更需 v2
- 业务 payload schema 演化按 [v1 schema evolution ADR](../../docs/architecture/202605031600-adr-v1-schema-evolution.md) 处理（response/event payload 禁 additionalProperties=false）

## 与现有 contract kind 的差异

| 维度 | event | sync | webhook |
|------|-------|------|---------|
| 传输 | AMQP/Kafka | gRPC/HTTP | HTTP（外部对接） |
| 方向 | pub/sub | call/reply | inbound/outbound 双向 |
| 签名 | 否 | 通常 TLS | HMAC-SHA256 强制 |
| 幂等 | consumer Claimer | 否 | Claimer（inbound）+ outbox delivery_id（outbound） |
| 重试 | broker | client | dispatcher Svix 8 步 |
| SSRF | N/A | N/A | dispatcher 强制 |
