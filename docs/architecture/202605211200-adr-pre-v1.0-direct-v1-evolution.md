# ADR: Pre-v1.0 Direct v1 Evolution Policy

- 时间: 2026-05-21
- 状态: Accepted
- 适用范围: 所有 `contracts/` 下的 wire 契约（HTTP / event / actors）
- ref: ADR `docs/architecture/202605031600-adr-v1-schema-evolution.md`（v1.0 GA 后的演化规则）
- ref: kubernetes/community `contributors/devel/sig-architecture/api_changes.md` §"Alpha versions" — alpha API breaking changes allowed without notice

## Context

GoCell 当前处于 pre-v1.0 阶段：没有生产部署、没有外部 API 消费方、没有 deprecation 告期需要照顾。原 `api-versioning.md` 写有 "删除/重命名字段 → 需要 v2 + 4 周 deprecation"，在 pre-v1.0 阶段是死规则——

- 没有 v1 实例固化，没有需要兼容的运行实例
- 无法演练 v1→v2 完整路径（J-03 CONTRACT-V1V2-DRY-RUN 卡在"找不到合适契约固化"）
- 字段命名漂移（J-04 CONTRACT-SCHEMA-NAMING-NORMALIZE: `event_id`/`request_id`/`pageSize`）若按 v2 升级走，会增加每个 contract 的 v1→v2 dry-run 成本 > 实际收益

K8s alpha API policy 给出工业先例：alpha 阶段允许 breaking change without notice，beta 后才进入兼容窗口。GoCell pre-v1.0 = alpha 等价。

## Decision

**v1.0 GA 之前**，wire 契约的 rename / remove / type-change 直接在 v1 下进行，**不创建 v2 副本、不保留 deprecation 别名、不写双字段并存 shim**。新规则、新 ADR、新 archtest 同 PR 闭环（per `feedback_constraint_self_close`）。

**v1.0 GA 触发后**，恢复完整 v2 升级 + 2 Sprint deprecation 政策：

1. 同 PR 内**重新写回** `api-versioning.md`：
   - §"何时升级版本" 第二条 bullet "删除/重命名字段、修改字段类型、修改必填参数 → 需要 v2"
   - §"向后兼容规则" 第 3 条 "Deprecation 至少保留 2 个 Sprint（4 周）"
2. 把 ADR 状态从 Accepted 改为 Superseded by `<v1.0 GA ADR>`
3. 不留 silent carry-over（feedback_no_lazy_deferral）

## Threat Model

| 风险 | 评估 | 缓解 |
|------|------|------|
| 丢失 v2 演练经验 | 中 | ADR 本身就是知识载体；v1.0 GA 时按 §Decision 第二段恢复。Enforcement: the v1.0 GA ADR's PR body MUST verbatim include this ADR's §Decision §2 checklist as items to verify; reviewers core-required to check off each line before approving the GA PR. No silent carry-over per feedback_no_lazy_deferral. |
| pre-v1.0 阶段"反正没人用"导致 wire 漂移 | 低 | archtest（CONTRACT-WIRE-FIELD-CAMELCASE-01 / -PAGINATION-PARAM-LIMIT-01 / -EVENT-IDEMPOTENCY-KEY-EVENTID-01）锁定 baseline 命名 |
| 外部 fork / 内部消费者依赖 pre-v1.0 接口 | 信息接受 | pre-v1.0 即声明 "API 不稳定"；GA 是承诺起点 |
| v1.0 GA 后忘记恢复 v2/deprecation 规则 | 中 | 本 ADR §Decision 显式列出"同 PR 写回 api-versioning.md"清单；GA ADR 必须按本清单逐条核销 |

## Out of scope

- DB schema migration 仍走 goose up/down + DestructiveDownPermit GUC 守卫（与本 ADR 无关，已有独立治理）
- Internal API (`/internal/v1/*`) 已经在 api-versioning.md 中独立声明"版本变更不需要 deprecation 告期"，与本 ADR 一致
- examples/ 目录下的契约本就 demo 用途，不在 v1.0 GA 承诺范围
- **Go SDK 公开符号 + authoring schema 的版本政策**：见 ADR `docs/architecture/202606131200-1088-adr-go-api-authoring-schema-semver-policy.md`（轴 A）；本 ADR 仅治 wire 契约（轴 B）。
