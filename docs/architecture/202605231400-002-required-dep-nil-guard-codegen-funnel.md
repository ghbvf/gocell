# ADR 002 — Required-Dep Nil Guard: Codegen Funnel

## Status

Accepted (2026-05-23)

## Context

**Issue #791** tracks that hand-written nil guards in `NewService` functions are
inconsistent, easy to skip, and produce different error codes and messages across
the codebase. Before this ADR, required-dependency nil checks were scattered as
ad-hoc `if s.x == nil { return nil, errcode.New(...) }` blocks at various points
in `NewService` bodies — some before the options loop, some after, some missing
entirely.

**PR #490 round-5 review experience**: the fifth review pass of PR #490 (session
protocol hardening) uncovered a P1 where `sessionvalidate.sessionStore` lacked
a nil guard, and `ordercreate.repo` was also unguarded. This demonstrated that
even experienced contributors do not reliably add guards when wiring a new field.

**OUTBOX-SERVICE-01** already guards `txRunner` as a special case across 12
outbox-bound services, but this leaves all other required fields (repos, codecs,
stores, issuers) unguarded. The asymmetry — one well-guarded field vs. many
ungarded fields — produces a false sense of safety.

**Soft → Hard upgrade motivation**: a string-convention approach ("remember to
add the guard") is Soft per `ai-collab.md §"AI-rebust 三档分级"`, and AI
co-authors regularly omit it. The codegen funnel lifts this invariant to Hard.

## Decision

Introduce a codegen funnel with three components:

1. **Source of truth**: `gocell:"required"` struct field tag on Service struct
   fields that must be non-nil at construction time. Optional fields
   (`logger`, `emitter`, `clock`) receive no tag. `clock` retains the
   `clock.MustHaveClock` panic guard (programmer-error class B semantics).

2. **Generator**: `tools/codegen/requireddepsgen` reads `service.go`, collects
   all `gocell:"required"` tagged fields in declaration order, and emits
   `service_required_gen.go` containing:

   ```go
   // Code generated by gocell generate required-deps. DO NOT EDIT.
   func (s *Service) validateRequired() error { ... }
   ```

   Each field emits either `if validation.IsNilInterface(s.field)` (interface
   type) or `if s.field == nil` (pointer type). Error kind/code/message are
   customisable via `gocellKind`, `gocellCode`, `gocellErr` sub-tags; defaults
   are `KindInternal / ErrCellInvalidConfig`.

3. **Call site**: `NewService` calls `s.validateRequired()` exactly once, after
   the options loop:

   ```go
   func NewService(..., opts ...Option) (*Service, error) {
       s := &Service{...}
       for _, o := range opts {
           o(s)
       }
       if err := s.validateRequired(); err != nil {
           return nil, err
       }
       return s, nil
   }
   ```

   Any additional post-options checks (e.g. `clock.MustHaveClock`, SessionTTL)
   follow `validateRequired()`.

### Archtest three-piece suite (A1–A4 + B1–B5)

- **A1** — `TestRequiredDepNilGuard_A1_GeneratorOutputGroundTruth`: regenerates
  every `service_required_gen.go` in-process and diffs bytes. Any hand-edit,
  stale file, or missed regeneration fails CI.
- **A2** — `TestRequiredDepNilGuard_A2_CallsiteUniqueness`: every `NewXxx`
  returning `(*Service, error)` must call `validateRequired()` exactly once,
  strictly after the options loop.
- **A3** — `TestRequiredDepNilGuard_A3_HandwrittenIsNilInterfaceBan`: bans
  `validation.IsNilInterface` calls in `service.go` (production only); all such
  calls must live in the generated file.
- **A4** — tag value whitelist: `gocell:` tag values must be in
  `{"required", ""}`.
- **B1–B5** — reverse self-tests closing reflect / MethodValue / external-helper
  bypass forms (see archtest package godoc).

## Why Hard

Per `ai-collab.md §"Funnel 双向锁评级"`:

| Direction | Mechanism | Rating |
|-----------|-----------|--------|
| Upstream (prevent hand-edit of gen file) | A1 regenerate-and-diff at byte granularity — any drift in `service_required_gen.go` is caught at CI | **Hard** |
| Upstream (prevent skipping validateRequired) | A2 callsite-uniqueness on (NewXxx, validateRequired) form — any omission or double-call caught | **Hard** |
| Downstream (prevent bypassing via IsNilInterface) | A3 bans hand-written `validation.IsNilInterface` in `service.go` | **Hard** |
| Downstream (reflect / MethodValue / external-helper bypass) | B1–B5 reverse self-tests assert these forms don't appear in production AST | **Hard** |

Both upstream and downstream sides are Hard → closed Hard funnel.

## Threat Matrix

| Threat | Guard | Rating |
|--------|-------|--------|
| Hand-edit `service_required_gen.go` to add fake field | A1 regen-diff catches byte deviation | Hard |
| Write `validation.IsNilInterface(s.x)` in `service.go` | A3 ban | Hard |
| Write `if s.X == nil` for a required interface field in `service.go` | B2 reverse self-test asserts this form absent | Hard |
| Use `reflect.ValueOf(s.X).IsNil()` in `service.go` | B1 reverse self-test | Hard |
| Pass `IsNilInterface` as method value or function pointer | B3 reverse self-test | Hard |
| Call third-party `MustNotBeNil` or similar helper | B4 ban list | Hard |
| Bind `validateRequired` as method value | B5 reverse self-test | Hard |
| Tag value typo (`gocell:"requied"`) | A4 whitelist rejects unknown values | Hard |
| `NewService` omits call to `validateRequired()` | A2 callsite uniqueness | Hard |
| `NewService` calls `validateRequired()` before options loop | A2 position check (post-options) | Hard |
| `sessionvalidate.sessionStore` unguarded (optional field by design) | by-design not tagged; its godoc declares optional | N/A |

## Open-Source Comparison

`uber-go/dig` and `uber-go/fx` enforce graph-completeness (every declared
dependency is provided) but do not enforce value-nil at runtime — a typed-nil
pointer satisfies the DI graph. `google/wire` enforces binding-Hard at codegen
time but again does not model value-nil. `nilaway` / `exhaustruct` static
analysers do not directly model the "option-injected required dep" invariant.
The codegen funnel + A1 golden diff is the highest achievable tier for this
rule shape in Go.

sub-conditions (outbox publish / import / DirectEmitter / WithOutboxWriter)
continue to operate alongside the new funnel.
